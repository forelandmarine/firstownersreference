# Layout spike and print-scale finding, 14 November 2026

Step 1 of `docs/print/layout-implementation-plan.md`. The lab route is `/print-lab/NN?grid=wide|side&head=a|b&anchors=…` (dev only), printed by `scripts/print-lab.mjs`. The PDFs are in `print/lab/` and are not committed, because `*.pdf` is ignored.

## 1. The book prints at 70 per cent

The proof's body text measures 8.9 pt in word height. The same text set by the same stylesheet on a lab page measures 12.7 pt, as 9.75 pt Newsreader should. Both routes compute `font-size: 9.75pt`. The difference is Chrome's shrink-to-fit: when the laid-out document is wider than the page, Chrome scales every page down until it fits.

Measured at the 190 mm type-area width (718 CSS px), the full book lays out 1,028 px wide. That predicts a scale of 0.698; the measured scale is 0.699. Two causes:

| Cause | Laid-out width | Scale it forces on its own | In the book since |
|---|---|---|---|
| One unbreakable URL in the sources section: `wwwcdn.imo.org/…/MSC.337(91).pdf` | 1,028 px | 0.70 | 3 May 2026 (efdc9c5) |
| 67 bleed figures (`.section-closer`, `.bleed-band`), 250 mm wide so they bleed off the trim | 831 px | 0.86 | 11 September 2026 (e042002) |

The same full book, printed from the dev server with two print-time CSS overrides and no source change (`.sources-section span { overflow-wrap: anywhere }`, and the bleed figures held to the type area):

| | Pages | Body word height |
|---|---|---|
| As built | 206 | 8.9 pt (70%) |
| URL fixed, bleeds left as they are | 253 | 11.0 pt (86%) |
| URL fixed, bleeds held to the type area | 291 | 12.7 pt (100%) |

`overflow: clip` with `overflow-clip-margin` on `.print-edition` does not stop the shrink. In-flow bleed cannot coexist with true scale; only standalone-merged pages (openers, plates) can bleed.

This is very likely the "217 pp at ~68% width" behaviour recorded in the pipeline notes, which was attributed to perturbations of the sources section. The URL has been there since May, so it is probably also why the 10 September three-column proof read as unreadable: it was printing at about 6.5 pt.

## 2. Grid and head pictures, measured at true scale

All nine lead essays, text-only depth in pages (fractional, to the last line), then with three head pictures each:

| | Wide 91.5 mm | Side column, 2 × 72 mm |
|---|---|---|
| Text only | 39.1 | 50.3 (+28%) |
| Head pictures, option A (new page per picture) | 65.2 | 77.9 |
| Head pictures, option B (spanning in the flow) | n/a | 68.1 |

The side-column grid costs 28 per cent more depth on running text, which matches the ratio of the text widths (144 against 183 mm). Option A costs about 0.97 pp per picture, including the short page it leaves behind. Option B costs about 0.66 pp per picture, but without the measuring loop it lands pictures at the foot of a page and strands crossheads beneath them (ch01, p. 1).

The side column mirrors correctly: on rectos the text sits at 27–177 mm, on versos at 59–209 mm.

## 3. Consequence for the plan

At true scale the book is already 291 pp before any layout change. The side-column grid would add roughly 50 pp of running text on top. The specification's fallback (section 10: keep the 91.5 mm columns) therefore applies now, and the extent question is no longer about the grid. It is about the type size, the copy length and the picture count.
